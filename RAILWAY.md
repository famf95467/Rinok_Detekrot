# Запуск на Railway (версия 1.11)

Файлы: app.py, ui.html, requirements.txt, Procfile, .gitignore (все в корне репозитория GitHub). Запустить.bat для облака не нужен.

1. Создайте ПРИВАТНЫЙ репозиторий на GitHub, загрузите эти 5 файлов. golden_key.txt и данные не загружайте.
2. Railway → New Project → Deploy from GitHub repo → выберите репозиторий.
3. Service → Variables, добавьте:
   - APP_USER = ваш логин
   - APP_PASSWORD = длинный пароль (12+ символов)
   - FUNPAY_GOLDEN_KEY = ваш golden_key
   - DATA_DIR = /data
4. Service → Settings → Volumes → Add Volume, Mount Path: /data (без тома данные пропадут при каждом деплое).
5. Settings → Networking → Generate Domain. Откройте адрес, введите логин и пароль.
6. Перенос данных с ПК: после первого запуска положите ваши json/csv (marks.csv, lot_merges.json, autopilot_settings.json и т.д.) в /data через Railway CLI (`railway ssh`) или начните с чистого листа.
7. Проверка: в логах строка «Облачный режим ... ключ из переменной: да»; страница просит пароль; на вкладке «Аккаунт» виден ваш ник.

Риски:
- по факту: golden_key даёт полный доступ к аккаунту. Храните только в переменной Railway, репозиторий держите приватным, пароль длинный.
- моя оценка: FunPay может отреагировать на вход с IP дата-центра (капча, блокировка сессии). Защита с блокировкой сессии в программе есть, но гарантий нет. Сначала держите автопилот выключенным/без отправок 1–2 дня и смотрите логи.
- Автопилот шлёт сообщения и делает возвраты без вас: настройки перенесены как на ПК.
- Законы, оплату и правила площадки проверяете вы сами.
