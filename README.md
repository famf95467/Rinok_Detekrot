# FunPay Detector 1.16.1

Локальная программа для продавца FunPay (категория «Прочее GTA 5 RP», `/lots/1112/`): детектор рынка, управление своими лотами, автопилот, статистика, оповещения в Telegram. Проект «Бизнесс», язык интерфейса русский.

**Цель:** понять цены и спрос на скрипты и другие товары, найти новые ниши, разгрузить рутину продавца.

## Файлы
- `app.py`: весь бэкенд (оглавление в начале файла, ищите `# ===== N.`).
- `ui.html`: весь интерфейс.
- `Запустить.bat`: запуск на ПК (или `python app.py`).
- `README.md`: этот файл, читать первым.

Нужны только Python 3 и `beautifulsoup4` (`pip install beautifulsoup4`).

## Правила (не менять без решения «Бизнесс»)
1. Ничего не обходим: капча, 401/403/429, редирект на вход останавливают сессию, повторов нет.
2. Любая правка лота только через «было → стало» и подтверждение.
3. Деньги (возврат) и сообщения покупателям: только по включённым галочкам, с лимитами; пауза после ошибки возврата снимается только вручную в интерфейсе.
4. Секреты (golden_key, токен Telegram, пароль) не пишутся в журналы, ответы API и копии.
5. Продажи по чужим лотам программа считает только как ОЦЕНКУ по падению остатка (вкладка «Продажи», раздел 8е, решение пользователя 15.11.2026); отзывы дают оценку спроса, не факт. Выручка по чужим лотам = продано × цена, тоже оценка.
6. Правила площадки и оплату проверяет пользователь сам.

## Запуск и настройка
- **ПК:** `Запустить.bat`, откроется браузер на `127.0.0.1`.
- **Облако (Railway):** задан `APP_PASSWORD` (от 12 символов), данные на томе `DATA_DIR`, ключ в `FUNPAY_GOLDEN_KEY`.
- **Telegram:** `TG_BOT_TOKEN` и `TG_CHAT_ID` или файл `tg_token.txt` (строка 1 токен, строка 2 chat_id). Для облака и ПК лучше разные боты: иначе команды конфликтуют.

## Telegram 1.16: как устроено
- **Новый заказ:** из страницы `/orders/trade`, которую автопилот уже читает раз в цикл (`conf_sync`), своих запросов нет. Задержка оповещения до длины цикла (по умолчанию до 20 минут). Номера заказов, о которых сказали или которые увидели при первом запуске, лежат в `tg_orders.json` (на томе); первый запуск только запоминает, без потока. Заказ старше суток при первом появлении (дальняя страница) тоже только запоминается.
- **Статистика и сводка:** из `orders_cache.json` (обновляет шаг «Статистика» автопилота раз в ~3 часа, первые страницы списка заказов): выручка = подтверждённые («Закрыт»). Если данные неполные или старые, сообщение это пишет.
- **Сводка:** время и часовой пояс в `tg_settings.json` (`summary_time`, `tz`, `min_amount`); дата последней сводки в `tg_state.json`, после перезапуска дубля нет; если программа была выключена в час сводки, её догонят не позже чем через 3 часа.
- **Кнопки и команды** принимаются только из личного чата с вашим `chat_id` (и только от вас). Возвратов, смены цен и сообщений покупателям из Telegram нет. «Старт» по-прежнему не снимает паузу из-за ошибки возврата.

## Продажи по остатку (1.16.1): как устроено
- Раздел 8е `app.py`, вкладка «Продажи», настройки в `market_sales_settings.json` (включено, интервал 1–60 мин, номер категории, порог 10). Опрос по умолчанию выключен: включается галочкой после подтверждения.
- Каждый проход = один гостевой запрос `/lots/N/` (как загрузчик, раздел 3). Остаток берётся из `.tc-amount`; не число («10 000+») пропускается. Базовые остатки только в памяти: после перезапуска первый проход их запоминает, продаж нет.
- Блокировка, капча, редирект, 401/403/429/5xx: опрос останавливается до конца дня через общий `fetch_state.json` (автоснимок тоже), повторов нет. Если на странице нет остатков два прохода подряд, опрос выключается сам.
- События пишутся в `market_sales.csv` (время, категория, id, продавец, название, цена, было, стало, продано), счётчики проходов по дням в `market_sales_state.json`. Покупателей нет.
- Занижение: продажа и пополнение в одну минуту сливаются. Завышение: продавец сам убрал 1–10 штук. Проверено на локальном тестовом сервере; на живом сайте остаток в гостевой странице категории ещё не проверен.
- Telegram-алертов по продажам пока нет.

## Известные ограничения
- Время заказов с сайта и часы сервера (UTC на Railway) смешаны в старом коде разбора («сегодня, 09:05» берётся с датой сервера): границы «сегодня» в `/stats` могут сдвигаться на величину поправки для части заказов. Не исправлялось.
- Правка лота (apply) на живом сайте и поднятие подтверждались на 10.11.2026; после обновлений проверяйте на одном лоте.
- Со страницы категории видно не больше ~4000 лотов; «пропал» не значит «продан».
- С ПК в России Telegram может требовать VPN.
