# FunPay Detector: карта проекта

Читать первым (людям и агентам). Обновлено: 2026-11-13. Версия `app.py`: 1.0.

Локальная программа для продавца FunPay (ник **TalentSeller**, категория «Прочее GTA 5 RP», `/lots/1112/`): детектор рынка (цены скриптов), управление своими лотами, сообщения, напоминания покупателям, учёт подтверждения заказов, статистика. Запуск на ПК пользователя, наружу не открывается.

## 1. Файлы

| Файл | Что это |
|---|---|
| `Запустить.bat` | Запускает `app.py` (ищет `python` или `py -3`, при ошибке показывает причину) |
| `app.py` | Весь бэкенд (оглавление в шапке файла, искать по строке `# ===== N.`) |
| `ui.html` | Весь интерфейс, отдаётся сервером, ничего внешнего не грузит |
| `README.md` | Этот файл |

Остальное рядом с `app.py` это **данные**, в коде не правятся: `pages/` (сохранённые страницы категории), `history/` (CSV на снимок и `index.csv`), `marks.csv` (ручные отметки), `marks_before_shell.csv` (одноразовая копия, не трогать), `fetch_state.json`, `auto_settings.json`, `auto_log.csv`, `manage_log.csv`, `amounts_cache.json`, `orders_cache.json`, `lot_costs.json`, `reminders_log.json`, `confirm_orders.json`, `confirm_log.csv`, `tickets/`, `golden_key.txt` (секрет, см. правила).

Зависимости: Python 3 и `beautifulsoup4` (`pip install beautifulsoup4`). Больше ничего.

Запуск: двойной клик по `Запустить.bat` или `python app.py`. CLI: `python app.py fetch` (один запрос страницы категории + разбор), `python app.py parse страница.htm --date ГГГГ-ММ-ДД` (разбор локальной страницы).

## 2. Устройство `app.py`

1. Пути, константы, утилиты.
2. Правила разбора страницы категории (бывш. `parse_category.py`): фильтры лотов, отметки, срезы цен.
3. Гостевой загрузчик категории (бывш. `fetch_category.py`).
4. Клиент аккаунта по `golden_key` (бывш. `funpay_manage.py`): единый `site_request()`.
5. Детектор: отметки, снимки, цены, история, автоснимок (бывш. `detector_app.py`).
6. «Аккаунт»: вход, лоты, форма лота (двухшагово: «было → стало», потом отдельное «применить»), количество, поднятие. Все запросы через `guarded()`.
7. Сообщения: список диалогов, история, отправка (одно нажатие = одно сообщение, переписка на диск не пишется).
8. Напоминания покупателям: «Найти заказы» (один запрос `/orders/trade`) → список → «Отправить выбранным». Берутся заказы «Оплачен» старше 24 ч; один покупатель = одно сообщение; не чаще раза в 24 ч; не больше 3 напоминаний на заказ и 30 покупателей за раз.
8б. **Подтверждение заказов (этап 1)**: см. раздел 5.
9. Статистика: заказы, прибыль (оценка: себестоимость и комиссию вводит пользователь), позиция по цене, кандидаты на повышение цены.
10. HTTP-сервер и таблица маршрутов. Каждая вкладка = свой блок `ROUTES_*`, здесь они склеиваются. Обработчик: `функция(dict) -> (HTTP-код, dict)`.
11. Точка входа: `serve` (по умолчанию) | `fetch` | `parse`.

Как добавить вкладку: раздел с логикой и своим `ROUTES_X` в `app.py` + добавить `ROUTES_X` в склейку раздела 10 + вкладка в `ui.html`.

## 3. Правила проекта (решения пользователя, не менять без его слова)

- **Ничего не обходим.** Капча, 403/429/503/52x, редирект на вход: код останавливается, ничего не повторяет, не маскирует, не меняет заголовки. Для аккаунта сессия блокируется до перезапуска; для гостевого загрузчика повтор в тот же день запрещён. Дальше решает пользователь («Бизнесс»).
- Гостевой загрузчик: без входа, единственная cookie `cy=rub`. Проверка robots.txt отключена пользователем 04.11.2026 (`check_robots` оставлена, не вызывается); лимит проходов и интервал убраны тем же решением.
- Изменения на сайте (лот, сообщение) только после явного подтверждения пользователя, с показом «было → стало». Автоответов и рассылок нет.
- `golden_key` даёт полный доступ к аккаунту: хранится в памяти, в файл только по галочке, не выводить, не логировать, не пересылать. В логах пишутся путь и статус, значения полей нет; в сохранённых HTML вырезаны csrf-токен и `data-app-data`.
- Покупатели хранятся только по ID, текст переписки не сохраняется.
- Сервер слушает только `127.0.0.1`, страница под строгой CSP (ни скриптов, ни шрифтов, ни картинок снаружи).
- Продаж и выручки конкурентов не считаем: только цены витрины и отзывы (оценка). Всё помечается «факт» / «оценка».
- Адреса и разметка FunPay (`/users/ID/`, `/lots/offerEdit`, `/orders/trade`, `/chat/`, `/runner/`, `/lots/raise`) написаны по памяти и частично не проверены на живом сайте: при несовпадении код останавливается и просит файл или список классов, не угадывает.
- Законы и порядок получения оплаты пользователь проверяет сам.

## 4. Детектор рынка

Поток: загрузчик сохраняет страницу в `pages/kategoriya_ГГГГ-ММ-ДД[_ЧЧММСС].htm`, состояние защиты в `fetch_state.json` (результат «остановлен…» = повтор до конца дня запрещён, ответ сайта в `pages/_stop_ДАТА.html`). Разбор: воронка (игра GTA 5, тип «Прочее», чужие проекты SAMP/Majestic/NOVA/RMRP/Region RP отбрасываются, срок ровно 7 дней, признаки скрипта, цена в рублях). Неясные лоты размечаются вручную в `marks.csv` (`скрипт` / `ниша` / `нет`, ручная отметка сильнее правила). Срезы цен по отзывам продавца: до 50, 50–500, больше 500; вариант A (все) и B (без «ниша»). Вкладки: Отметки, Цены, Данные (кнопка «Обновить», автоснимок раз в N часов, по умолчанию 6), История (по снимку на день, график, новые/пропавшие лоты, прирост отзывов).

## 5. Подтверждение заказов (этап 1, раздел 8б)

Зачем: если покупатель забыл нажать «подтвердить», FunPay заказ сам не закрывает, нужен тикет в поддержку. Раздел ведёт учёт и готовит текст тикета. **Ничего не отправляет**: тикет отправляет пользователь вручную.

**Состояния:** `paid` (оплачен) → `delivered` (выдан) → `reminded` (напоминание отправлено, время, старт таймера 24 ч) → `confirmed` (подтверждён). Боковое: `refunded`. «Не подтвердил» не хранится, а вычисляется: `reminded` и с последнего напоминания прошло 24 ч. Повторное напоминание перезапускает таймер. Выдачу можно пропустить (paid → reminded). Нарушение порядка = отказ с записью в журнал, данные не меняются.

**Откуда данные:** вручную (маршруты ниже) и автоматически из раздела 8: `remind_scan` вызывает `conf_sync(rows, now)` (заводит «Оплачен», ставит confirmed/refunded по статусам «Закрыт»/«Возврат»), `remind_send_one` после успешной отправки вызывает `conf_on_reminded(orders)`. Это две добавленные строки в разделе 8 (в `try/except`, помечены комментарием).

**Данные:** `confirm_orders.json` (состояния), `confirm_log.csv` (журнал всех действий и отказов), `tickets/ticket_*.txt`.

**Тикет** (https://support.funpay.com/tickets/new): «Проблема с заказом» → ник `TalentSeller` → номер заказа (в форму первый из списка) → «Продавец» → тема «Покупатель забыл подтвердить заказ»; в комментарии список заказов: оплата, выдача (если известна), напоминание, ссылка на диалог. В тикет попадает заказ только при: статус `reminded` + прошло 24 ч + отметка `chat_ok`. Отметку ставит пользователь после проверки чата (услуга оказана, покупатель однозначно просто забыл подтвердить: это требование поддержки). Программа чат не читает и этого не проверяет. **Не ослаблять это условие и не ставить `chat_ok` автоматически.**

**API:** GET `/api/confirm/list?all=1&id=`; POST `/api/confirm/` + `add{id,lot,price,buyer,at}`, `deliver{id,at}`, `remind{id,at}`, `confirm{id,at}`, `chat-ok{id,url,off}`, `note{id,note}`, `ticket{ids,again}`, `ticket-sent{ids}`, `sync` (нужен вход, один запрос `/orders/trade`). `at` необязательно, формат `ГГГГ-ММ-ДД ЧЧ:ММ`. Ошибки ввода и отказы: HTTP 400 с понятным текстом.

## 6. Дорожная карта заказов

0. Что разрешает FunPay: выяснено пользователем (автоподтверждения нет, нужен тикет; подарок за отзыв разрешён).
1. **Ядро: готово** (раздел 5). Интерфейса (вкладка «Заказы» в `ui.html`) пока нет.
2. Просьба об отзыве после подтверждения, свой шаблон на лот. Награда («5 звёзд → N единиц товара», настройка на лот) разрешена. Не начато.
3. Автовозврат при 1–3 звёздах с порогом суммы X. Мнение разработчика: рискованно (похоже на манипуляцию отзывами, прямые потери). Предложено сначала только уведомление «плохой отзыв, заказ N, сумма M» и решение вручную. Решения пользователя нет, не начато.
4. Проверка: тесты на тестовых данных, затем 1–2 живых заказа под контролем пользователя.
